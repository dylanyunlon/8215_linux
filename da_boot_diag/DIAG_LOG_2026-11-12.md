# DA 树 NAND-256 板循环重启：排查全记录（2026-11-12 ~ 11-13）

板子：AC8215，NAND 256M / DDR 256M（`MemTotal` 183132 kB），adb 实测分区与 `nand-256-ddr-256` 一致。
现象：DA 树 `-a nand-256-ddr-256` 的包，开机动画播完约 **18 秒**重启，循环；串口无输出；RAM console（`/proc/last_kmsg`）在这块板上读不到上一次日志（MARKER 测试）。

## 结论

**元凶：DA 树 `prebuild/atc_ftl/atc_lib.a`（NAND FTL 核心，闭源，被链进内核）。**

| | DA 树 | 旧树（OLD_nand256 / AWTK 树） |
|---|---|---|
| MD5 | `129f1bfec7cb354040104c6e734aeca2` | `21c5372b372a342f6b0b92245c7d22a7` |
| 大小 / 日期 | 838706 B / 2026-09-16 | 841942 B / 2026-06-10 提交 |
| 版本串 | 无 | `[MTKLib]Version 2026020331`（启动时打印 `FTL Lib Version`） |
| 其他 | 所在 `prebuild/` 无 git 历史；用到 `panic_*` 符号字符串 | `prebuild/atc_ftl` 是 git 仓库；用到 `complete_all` |

实测依据：同一份 DA 源码、同一份 `.config`（零漂移）、同一套 dtb/rootfs，**只把这一个库换成旧树的**（变体 G12），18 秒重启消失。
**机制未知**（库是闭源的，没有日志）：怀疑库里有后台线程或定时器，这只是推断。DA 的 `atcftlcore.c` 也比旧树老（缺 discard、`blk_cleanup_queue`、`pm_lock` 修复），没有单独验证 `atcftlcore.c` 的责任（H2/H3 已编好未刷）。

`nor-64-ddr-256` 是同事（另一账号）在同一台整编机上跑的 NOR 板参数，与本板无关；本板是 `nand-256-ddr-256`。

## 方法（可复用）

1. **四象限**：内核（旧/DA）×其余（引导链、arm2、dtb、分区、rootfs）。旧内核套 DA 整套能稳定起、adb 通 ⇒ 问题只在 DA 编出的内核。
2. **`initcall_blacklist=`**（3.18.49 带；DA `KALLSYMS=y`）：只改 dtb 的 bootargs 就能跳过某个内置驱动的初始化，不用重编。名单来自两份 `System.map` 的 `__initcall_*` 差集。**必须做阳性对照**（挡 `init_vfat_fs,init_msdos_fs`，`/proc/filesystems` 里确实少了 vfat/msdos，`dmesg` 有 `blacklisted`）。参数总长要低于 `COMMAND_LINE_SIZE=1024`（旧底座实测 550，加 25 个名字约 900）。
3. **手工快速编内核**：`xtool_build.sh`。必须带 `AC83XX_BOOT_DEVICE=nand` 和 `TOPDIR=<树根>/buildroot`，编完核对 `.config` 漂移（应 0 行）和 `zImage` 大小（应与原版差几十字节）。
4. **换预编译库**：造"假根"目录，`prebuild/` 下的子目录用符号链接指向旧树或 DA 树的对应库，再把 `TOPDIR` 指过去。

## 已排除 / 已撤回

- **metazone 先于 NAND 初始化**：撤回。DA 里是 `late_initcall(mtz_init)`（旧树快照里才是 `module_init`）。`diag_nomtz` 未做，也不再需要。
- **MCU 冷启动握手**：`mcu_cold_handshake` 只在 `BUILD_TEST` 下才编（`-m` 不是 `BUILD_TEST`，`-t` 才是），且驱动只建两个 sysfs 节点，无超时无重启。
- **bootanidrv `rsv_free_thread`**：`wait_event_interruptible(rsv_free_queue, 1)` 条件恒真，内核启动即 `free_memblock_runtime` 释放动画保留内存，是代码缺陷；但注释掉后仍重启，**不是主因**（建议告知同事）。
- **WiFi/COMBO**：`ATC_COMBO` 必须 `=y`（`builtin.o` 被内置的 `nl80211.c` 引用），改 `=m` 链接失败；不是原因。
- **DA 独有/共有被改的 initcall、NAND 控制器 probe（`diag_nonand`）、dts、根挂载、配置差异（98 行，无 NAND/BOOT_DEVICE/WDT/PANIC 类）、内核体积压保留内存、`nosmp`/`clk_ignore_unused`、工具链**：均排除。
- **串口、RAM console**：这块板上不可用。

## 踩坑

- 手工编内核漏 `AC83XX_BOOT_DEVICE` ⇒ Kconfig 静默砍掉 MTD/NAND/JFFS2，内核挂不上根分区，停在最后一帧、不重启、无 adb——**看起来像"换工具链改变了行为"，其实不是**。漏 `TOPDIR` ⇒ `cp: cannot stat '/../prebuild/atc_ftl/atc_lib.a'`。（前几轮 A/A2/B' 因此作废。）
- 刷机后的**第一次启动**比后续长（约 60 秒对 18 秒），计时要排除它；每次冷启动先断电 10 秒。
- `allmake.sh` 失败后仍会打包，`release_images` 里可能是上一次的 `Image.bin`；做包前核对 `Build error` 个数和时间戳。
- 终端里把带 `#` 注释的命令粘进 `adb shell` 会乱码；`tail -2 a b` 要写成 `tail -n 2 a b`。
- `mk_diag_pkg.sh` 打印的第一组 MD5 是**拷贝内核之前**的，以 `cp` 之后再跑的 `md5sum` 为准。
